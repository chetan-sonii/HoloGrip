System Architecture

From physical movement to a 3D object.

HoloGrip follows a sequential motion-processing pipeline. The MPU6050 captures acceleration and rotational movement. The ESP32 receives the sensor data, performs sensor fusion, represents orientation using quaternions, and sends the resulting orientation information through Bluetooth to Python. Python then uses that information to control the orientation of a 3D object.

Core Technologies

The technologies that make HoloGrip work.

Each component has a specific role in converting physical hand movement into usable orientation data and finally into 3D interaction.

MPU6050 6-axis inertial sensor containing an accelerometer and gyroscope for detecting motion.
ESP32 Microcontroller responsible for reading sensor data and executing the motion-processing pipeline.
Sensor Fusion Combines inertial measurements to obtain a more useful estimate of device orientation.
Quaternion Represents three-dimensional orientation while avoiding the limitations of Euler-angle rotation.
Bluetooth Provides the wireless communication link between the ESP32 and the Python application.
Python Receives the orientation information and maps it to the movement of the 3D object.
Why This Pipeline?

A complete motion interaction chain.

HoloGrip does not simply send raw sensor values to a computer. The data is processed progressively so that physical movement can be represented as meaningful three-dimensional orientation.

01
Sense the movement

The MPU6050 detects acceleration and angular velocity produced by the movement of the device.

02
Calculate orientation

The ESP32 processes the measurements through sensor fusion and maintains the orientation as a quaternion.

03
Control the 3D object

Orientation data is sent through Bluetooth to Python, where it is applied to the corresponding 3D object.
